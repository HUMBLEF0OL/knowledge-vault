### **Stage 3: Intermediate Node.js Concepts**

#### **3. Express Middleware and Advanced Features**

Express middleware functions are the backbone of request handling in Express applications, as they allow you to customize request processing, add new functionality, and modularize code. We’ll also go into error handling, request validation, and the basics of authentication.

---

##### **3.1 Types of Middleware**

1. **Application-level Middleware**: Applied globally across the app using `app.use()`.

   ```javascript
   const express = require('express');
   const app = express();

   app.use((req, res, next) => {
     console.log('Application-level middleware');
     next();  // Passes control to the next middleware or route handler
   });
   ```

2. **Router-level Middleware**: Defined on specific routers using `router.use()`.

   ```javascript
   const router = express.Router();

   router.use((req, res, next) => {
     console.log('Router-level middleware');
     next();
   });
   ```

3. **Built-in Middleware**: Express includes some built-in middleware functions like `express.json()` for JSON parsing, and `express.static()` for serving static files.

4. **Error-handling Middleware**: A middleware with four parameters (`err, req, res, next`) specifically for handling errors.

---

##### **3.2 Using Middleware in Express**

Middleware can be used for several purposes, including logging, modifying requests/responses, and handling errors.

**Example**: Logging Middleware

```javascript
app.use((req, res, next) => {
  console.log(`Request Method: ${req.method}, URL: ${req.url}`);
  next();
});
```

**Example**: Authentication Middleware (pseudo-authentication)

```javascript
app.use((req, res, next) => {
  const isAuthenticated = req.headers.authorization === 'my-secret-token';
  if (isAuthenticated) {
    next();
  } else {
    res.status(403).send('Forbidden');
  }
});
```

---

##### **3.3 Error Handling in Express**

Error-handling middleware is a specialized function that captures errors and handles them appropriately.

**Example**:

```javascript
app.use((err, req, res, next) => {
  console.error(err.stack);
  res.status(500).send('Internal Server Error');
});
```

- **Explanation**: The error-handling middleware is added at the end of all routes, so it catches any errors that weren’t handled by previous middleware or route handlers.

**Example with Route-level Error**:

```javascript
app.get('/error', (req, res, next) => {
  const error = new Error('Something went wrong');
  next(error);  // Passes the error to the error-handling middleware
});
```

##### **3.4 Request Validation with Middleware**

Express doesn’t provide built-in validation, but popular libraries like `express-validator` make it easy to validate request data.

1. **Install** the library:

   ```bash
   npm install express-validator
   ```

2. **Example**: Using `express-validator` to validate user input in a signup form.

   ```javascript
   const { body, validationResult } = require('express-validator');

   app.post('/signup', [
     body('email').isEmail().withMessage('Enter a valid email'),
     body('password').isLength({ min: 6 }).withMessage('Password must be at least 6 characters long')
   ], (req, res) => {
     const errors = validationResult(req);
     if (!errors.isEmpty()) {
       return res.status(400).json({ errors: errors.array() });
     }
     res.send('Signup successful');
   });
   ```

- **Explanation**: This example ensures that the `email` field is a valid email and the `password` field has a minimum length of 6 characters. If validation fails, it returns a `400 Bad Request` status with an array of error messages.

##### **3.5 Advanced Middleware Patterns**

1. **Conditional Middleware**: You can conditionally apply middleware based on certain conditions.
   
   ```javascript
   app.use((req, res, next) => {
     if (req.path === '/special') {
       console.log('Special path middleware');
     }
     next();
   });
   ```

2. **Middleware Composition**: Organizing middleware into reusable functions for cleaner code.

   ```javascript
   const requireAuth = (req, res, next) => {
     const isAuth = req.headers.authorization === 'auth-token';
     if (isAuth) {
       next();
     } else {
       res.status(403).send('Unauthorized');
     }
   };

   app.use('/secure', requireAuth);  // Only apply to routes under /secure
   ```

##### **3.6 Authentication with Express and JSON Web Tokens (JWT)**

Authentication is critical for building secure applications. One common method in REST APIs is JSON Web Tokens (JWT), where tokens are used to verify users without needing to send passwords.

1. **Install the JWT libraries**:

   ```bash
   npm install jsonwebtoken
   ```

2. **Generating a JWT**:

   ```javascript
   const jwt = require('jsonwebtoken');
   const SECRET_KEY = 'my-secret-key';

   app.post('/login', (req, res) => {
     const user = { id: 1, username: 'user' };  // Example user data
     const token = jwt.sign(user, SECRET_KEY, { expiresIn: '1h' });
     res.json({ token });
   });
   ```

3. **Verifying a JWT**:

   ```javascript
   const authenticateToken = (req, res, next) => {
     const token = req.headers['authorization'];
     if (!token) return res.status(401).send('Access Denied');

     jwt.verify(token, SECRET_KEY, (err, user) => {
       if (err) return res.status(403).send('Invalid Token');
       req.user = user;  // Attach user data to the request
       next();
     });
   };

   app.get('/secure-data', authenticateToken, (req, res) => {
     res.send('This is secured data');
   });
   ```

   - **Explanation**: In the `/login` route, a JWT is created using the `jwt.sign` method. The `authenticateToken` middleware verifies the token on protected routes, attaching user data if successful.

##### **3.7 Rate Limiting Middleware**

Rate limiting controls the number of requests a user can make to the server, which can help prevent abuse and DDoS attacks. A popular library for rate limiting in Express is `express-rate-limit`.

1. **Install the library**:

   ```bash
   npm install express-rate-limit
   ```

2. **Usage**:

   ```javascript
   const rateLimit = require('express-rate-limit');

   const limiter = rateLimit({
     windowMs: 15 * 60 * 1000,  // 15 minutes
     max: 100,  // Limit each IP to 100 requests per windowMs
     message: 'Too many requests, please try again later.'
   });

   app.use('/api/', limiter);  // Apply rate limiting to all routes starting with /api
   ```

- **Explanation**: The rate limiter will allow only 100 requests per 15 minutes from each IP. If the limit is exceeded, the user receives an error message.

##### **3.8 Serving Static Files with Express**

Express provides a straightforward way to serve static assets like HTML, CSS, JavaScript, and image files using the `express.static` middleware.

1. **Serving Files**:

   ```javascript
   app.use(express.static('public'));
   ```

2. **Example**: Place your static assets (e.g., `styles.css`, `script.js`) inside a `public` directory, and you can access them directly:

   - `http://localhost:3000/styles.css`
   - `http://localhost:3000/script.js`

3. **Explanation**: `express.static` serves files in the specified folder (`public` in this case). This can be useful for serving an HTML-based frontend or images for a REST API.

---

##### **3.9 Modular Routing**

Express allows you to modularize routes by organizing them into separate files, making your application more maintainable.

**Example**:

1. **Create a new router file** (`routes/users.js`):

   ```javascript
   const express = require('express');
   const router = express.Router();

   router.get('/', (req, res) => {
     res.send('User List');
   });

   router.post('/', (req, res) => {
     res.send('Create User');
   });

   module.exports = router;
   ```

2. **Use the router in your main app** (`app.js`):

   ```javascript
   const express = require('express');
   const app = express();
   const userRoutes = require('./routes/users');

   app.use('/users', userRoutes);  // Mount the router on /users
   ```

- **Explanation**: By organizing routes in separate files, you can maintain larger applications more easily, focusing on each feature or section individually.
