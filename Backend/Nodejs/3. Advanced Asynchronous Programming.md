### **Stage 3: Intermediate Node.js Concepts**

#### **2. Advanced Asynchronous Programming**

Node.js is built on an asynchronous, non-blocking model, which is key for creating scalable applications. Here’s an in-depth look at different ways to handle asynchronous tasks in Node.js.

---

##### **2.1 Callbacks**

Callbacks were the original way to handle asynchronous operations in JavaScript and Node.js. However, they can lead to "callback hell" if nested excessively.

**Example**: Reading a file using callbacks

```javascript
const fs = require('fs');

fs.readFile('example.txt', 'utf8', (err, data) => {
  if (err) {
    console.error('Error reading file:', err);
    return;
  }
  console.log('File data:', data);
});
```

- **Explanation**: The callback function is executed once the file read operation completes or encounters an error.
- **Drawback**: Callbacks can become challenging to manage when multiple asynchronous operations are nested, leading to less readable and harder-to-maintain code.

---

##### **2.2 Promises**

Promises were introduced to improve readability and error handling in asynchronous code. A Promise represents a value that may be available now, or in the future, or may never resolve (fail).

- **Creating and Using Promises**:
  ```javascript
  const fs = require('fs').promises;

  fs.readFile('example.txt', 'utf8')
    .then(data => {
      console.log('File data:', data);
    })
    .catch(err => {
      console.error('Error reading file:', err);
    });
  ```

**Example**:
Here’s how you can wrap a callback-based function in a Promise.

```javascript
const doSomethingAsync = () => {
  return new Promise((resolve, reject) => {
    setTimeout(() => {
      const success = true;  // Simulating success
      if (success) {
        resolve('Operation successful');
      } else {
        reject('Operation failed');
      }
    }, 1000);
  });
};

doSomethingAsync()
  .then(result => console.log(result))
  .catch(error => console.error(error));
```

- **Explanation**: Here, `doSomethingAsync` is a promise-based function that resolves or rejects based on the operation’s outcome.

---

##### **2.3 Async/Await**

Async/await, introduced in ES2017, is syntactic sugar over Promises, making asynchronous code look and behave more like synchronous code. An `async` function always returns a Promise, and `await` can be used within `async` functions to pause execution until the Promise resolves.

**Example**: Reading a file with async/await

```javascript
const fs = require('fs').promises;

async function readFileAsync() {
  try {
    const data = await fs.readFile('example.txt', 'utf8');
    console.log('File data:', data);
  } catch (error) {
    console.error('Error reading file:', error);
  }
}

readFileAsync();
```

- **Explanation**: The `await` keyword pauses the function execution until the `readFile` Promise resolves or rejects. This makes the code more readable and easier to manage, especially when dealing with multiple asynchronous operations.

**Example Use Case**:
In a database operation, async/await can be used to perform sequential steps like querying data, transforming it, and updating a record, all in a readable manner.

---

##### **2.4 Handling Multiple Promises**

In real-world applications, you often need to perform multiple asynchronous operations concurrently or sequentially. JavaScript provides utilities like `Promise.all`, `Promise.allSettled`, `Promise.any`, and `Promise.race` for handling such cases.

1. **Promise.all**:
   - Waits for all Promises to resolve and returns an array of their results. If any Promise rejects, it returns the rejection immediately.
   ```javascript
   const fetchData1 = () => Promise.resolve('Data 1');
   const fetchData2 = () => Promise.resolve('Data 2');

   Promise.all([fetchData1(), fetchData2()])
     .then(results => console.log(results))  // ['Data 1', 'Data 2']
     .catch(error => console.error('Error:', error));
   ```

2. **Promise.allSettled**:
   - Waits for all Promises to either resolve or reject and returns an array of their statuses and values/errors. It’s useful when you want all results, regardless of individual failures.
   ```javascript
   Promise.allSettled([fetchData1(), fetchData2()])
     .then(results => console.log(results));
   ```

3. **Promise.any**:
   - Resolves as soon as one of the Promises resolves, ignoring any rejections. It’s useful when you want only one successful result.
   ```javascript
   Promise.any([fetchData1(), fetchData2()])
     .then(result => console.log(result))
     .catch(error => console.error('All promises rejected', error));
   ```

4. **Promise.race**:
   - Resolves or rejects as soon as any one of the Promises completes. It’s useful for tasks where only the quickest result matters.
   ```javascript
   Promise.race([fetchData1(), fetchData2()])
     .then(result => console.log(result))
     .catch(error => console.error(error));
   ```

##### **2.5 Concurrency Control**

JavaScript provides concurrency control with functions like `Promise.all`, but when you need to limit the number of concurrent operations (e.g., making API requests to avoid rate limits), you may need a custom approach.

**Example**: Throttling with a Promise queue

```javascript
async function limitedConcurrency(tasks, limit) {
  const results = [];
  const executing = [];
  
  for (const task of tasks) {
    const promise = Promise.resolve().then(() => task());
    results.push(promise);
    
    if (limit <= tasks.length) {
      const e = promise.then(() => executing.splice(executing.indexOf(e), 1));
      executing.push(e);
      if (executing.length >= limit) {
        await Promise.race(executing);
      }
    }
  }
  return Promise.all(results);
}

const sampleTasks = [fetchData1, fetchData2]; // Array of functions returning promises
limitedConcurrency(sampleTasks, 2)
  .then(results => console.log(results))
  .catch(err => console.error(err));
```

- **Explanation**: This code limits the number of concurrent tasks to `limit`, using a queue to track executing tasks.

**Example Use Case**:
You may use concurrency control to make a large number of API requests in batches, ensuring that only a specified number run at a time to avoid overloading the server.

##### **2.6 Error Handling in Asynchronous Code**

Error handling with async/await should always include `try/catch` blocks around `await` expressions to prevent the app from crashing due to unhandled errors.

**Example**:

```javascript
async function fetchData() {
  try {
    const response = await someAsyncOperation();
    return response;
  } catch (error) {
    console.error('Error fetching data:', error);
    return 'Default data';  // Returning default or fallback data
  }
}
```

- **Best Practices**:
  - Always handle rejected promises to prevent unhandled promise rejections.
  - Log errors for debugging and provide meaningful error messages for users.
