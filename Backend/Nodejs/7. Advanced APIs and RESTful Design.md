### **Advanced APIs and RESTful Design**

#### **1. Introduction to REST**

**REST** (Representational State Transfer) is an architectural style for designing networked applications. It relies on a stateless communication protocol, usually HTTP, and uses standard methods for operations.

---

##### **1.1 Principles of REST**

1. **Statelessness**:
   - Each request from a client must contain all the information needed to process the request.
   - The server should not store any session state between requests.

2. **Resource-Based**:
   - Everything is treated as a resource, identified by a URI (Uniform Resource Identifier).
   - Resources are manipulated using standard HTTP methods.

3. **Uniform Interface**:
   - REST APIs should have a consistent and uniform interface, allowing different clients to interact with the same API seamlessly.

4. **Client-Server Separation**:
   - The client and server should be independent of each other, allowing them to evolve separately.

5. **Cacheability**:
   - Responses from the server can be marked as cacheable or non-cacheable to improve performance.

---

#### **2. Designing RESTful APIs**

When designing a RESTful API, consider the following best practices:

---

##### **2.1 Use Appropriate HTTP Methods**

- **GET**: Retrieve data (read-only operation).
- **POST**: Create a new resource.
- **PUT**: Update an existing resource.
- **DELETE**: Remove a resource.
- **PATCH**: Partially update a resource.

---

##### **2.2 Resource Naming Conventions**

- Use nouns to represent resources (e.g., `/users`, `/products`).
- Use plural nouns for resource collections (e.g., `/users` instead of `/user`).
- Use hierarchical structure to represent relationships (e.g., `/users/{userId}/posts`).

---

##### **2.3 Versioning**

- Include the API version in the URI to maintain backward compatibility (e.g., `/api/v1/users`).
- Alternatively, use headers for versioning.

---

##### **2.4 Status Codes**

- Use standard HTTP status codes to indicate the outcome of a request:
  - **200 OK**: Request was successful.
  - **201 Created**: Resource was created successfully.
  - **204 No Content**: Request was successful, but no content to return.
  - **400 Bad Request**: The request was invalid.
  - **401 Unauthorized**: Authentication is required.
  - **403 Forbidden**: Access is denied.
  - **404 Not Found**: Resource not found.
  - **500 Internal Server Error**: An error occurred on the server.

---

#### **3. Implementing a RESTful API in Express**

Let’s implement a simple RESTful API using Express. We will create a CRUD API for managing users.

---

##### **3.1 Setting Up the Project**

1. **Initialize a new Node.js project**:

   ```bash
   mkdir rest-api-example
   cd rest-api-example
   npm init -y
   npm install express body-parser
   ```

2. **Create the main file**:

   ```bash
   touch app.js
   ```

---

##### **3.2 Example Code**

```javascript
const express = require('express');
const bodyParser = require('body-parser');

const app = express();
app.use(bodyParser.json());

let users = []; // In-memory user storage for demonstration

// GET /api/v1/users - Retrieve all users
app.get('/api/v1/users', (req, res) => {
  res.status(200).json(users);
});

// POST /api/v1/users - Create a new user
app.post('/api/v1/users', (req, res) => {
  const user = {
    id: users.length + 1,
    name: req.body.name,
    email: req.body.email,
  };
  users.push(user);
  res.status(201).json(user);
});

// GET /api/v1/users/:id - Retrieve a user by ID
app.get('/api/v1/users/:id', (req, res) => {
  const user = users.find(u => u.id === parseInt(req.params.id));
  if (!user) return res.status(404).send('User not found');
  res.status(200).json(user);
});

// PUT /api/v1/users/:id - Update a user by ID
app.put('/api/v1/users/:id', (req, res) => {
  const user = users.find(u => u.id === parseInt(req.params.id));
  if (!user) return res.status(404).send('User not found');

  user.name = req.body.name;
  user.email = req.body.email;
  res.status(200).json(user);
});

// DELETE /api/v1/users/:id - Delete a user by ID
app.delete('/api/v1/users/:id', (req, res) => {
  const userIndex = users.findIndex(u => u.id === parseInt(req.params.id));
  if (userIndex === -1) return res.status(404).send('User not found');

  users.splice(userIndex, 1);
  res.status(204).send(); // No content to return
});

// Start the server
app.listen(3000, () => {
  console.log('Server is running on http://localhost:3000');
});
```

#### **4. Advanced Features**

##### **4.1 Pagination**

- When dealing with large datasets, implement pagination to limit the number of results returned.
- Use query parameters for pagination:

  ```javascript
  app.get('/api/v1/users', (req, res) => {
    const page = parseInt(req.query.page) || 1;
    const limit = parseInt(req.query.limit) || 10;
    const startIndex = (page - 1) * limit;
    const endIndex = page * limit;

    const results = {};
    results.results = users.slice(startIndex, endIndex);
    res.json(results);
  });
  ```

---

##### **4.2 Filtering and Sorting**

- Allow filtering and sorting by implementing query parameters:

  ```javascript
  app.get('/api/v1/users', (req, res) => {
    const { sort, filter } = req.query;
    let filteredUsers = users;

    if (filter) {
      filteredUsers = users.filter(user => user.name.includes(filter));
    }
    
    if (sort) {
      filteredUsers.sort((a, b) => (a.name > b.name ? 1 : -1));
    }

    res.json(filteredUsers);
  });
  ```
