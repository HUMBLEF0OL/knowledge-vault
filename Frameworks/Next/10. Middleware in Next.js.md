## **Chapter 10: Middleware in Next.js**

Middleware is an essential feature in Next.js that allows you to run custom code before a request is completed. This enables you to handle various scenarios such as authentication, logging, redirects, and more. In this chapter, we will explore how to create and use middleware, along with examples and benefits of running middleware on the Edge for enhanced performance.

---

### **10.1 Creating and Using Middleware for Request Handling**

Middleware in Next.js can be defined in the `middleware.js` file located in the root of the project or within specific folders in the `app/` directory. The middleware can intercept requests, modify the response, or even redirect users based on certain conditions.

#### **Basic Structure of Middleware**

Here’s a simple example of a middleware function:

```javascript
// middleware.js
import { NextResponse } from 'next/server';

export function middleware(request) {
  // Perform some checks or logic
  const { pathname } = request.nextUrl;

  // If user is not authenticated, redirect to the login page
  if (pathname.startsWith('/protected') && !request.cookies.get('auth-token')) {
    return NextResponse.redirect(new URL('/login', request.url));
  }

  // Continue to the requested page
  return NextResponse.next();
}
```

- **NextResponse**: This is used to create a response for the request. You can redirect, modify headers, or continue processing the request.

### **10.2 Examples of Middleware Usage**

Middleware can be used in various scenarios. Here are some common use cases:

#### **1. Authentication Middleware**

You can create middleware to protect certain routes from unauthenticated access:

```javascript
export function middleware(request) {
  const isAuthenticated = request.cookies.get('auth-token');

  if (!isAuthenticated) {
    return NextResponse.redirect(new URL('/login', request.url));
  }

  return NextResponse.next();
}
```

#### **2. Logging Middleware**

Logging middleware can be useful for tracking requests and responses:

```javascript
export function middleware(request) {
  console.log(`Request made to: ${request.nextUrl.pathname}`);
  return NextResponse.next();
}
```

#### **3. Redirects Middleware**

Redirect users based on specific conditions, such as enforcing a specific URL structure:

```javascript
export function middleware(request) {
  const { pathname } = request.nextUrl;

  // Redirect to a trailing slash version of the URL if it doesn't have one
  if (pathname.endsWith('/') || pathname.includes('.')) {
    return NextResponse.next();
  }

  return NextResponse.redirect(new URL(`${pathname}/`, request.url));
}
```

### **10.3 Running Middleware on the Edge for Faster Performance**

Next.js allows you to run middleware at the Edge, which provides low-latency execution closer to the user. This can improve performance for applications with global audiences.

#### **Benefits of Edge Middleware**

1. **Faster Response Times**: By running middleware at the Edge, requests can be handled closer to the user, resulting in faster response times.

2. **Reduced Server Load**: Offloading processing to Edge locations can help reduce the load on your main server.

3. **Geolocation Awareness**: You can customize responses based on the user’s geographic location, improving user experience.

#### **Enabling Edge Middleware**

To run middleware at the Edge, you simply need to include the `runtime` directive in your `middleware.js` file:

```javascript
// middleware.js
import { NextResponse } from 'next/server';

export const config = {
  runtime: 'edge',
};

export function middleware(request) {
  // Your middleware logic
  return NextResponse.next();
}
```
