## **Chapter 2: File-Based Routing with App Router in Next.js**

In this chapter, we will explore the file-based routing system introduced with the App Router in Next.js. This system allows you to create routes and manage application structure through the directory and file names, streamlining the process of building a web application.

---

### **2.1 Basics of the App Router (`app/` directory)**

The App Router is a new routing mechanism in Next.js, introduced to enhance the routing capabilities of applications. The main features of the App Router include:

- **File-based routing**: Define routes using the folder and file structure within the `app` directory.
- **Automatic code splitting**: Each route is treated as a separate entry point, leading to optimized loading performance.

#### **Key Features:**

- Improved layout management with the ability to define layouts per route.
- Seamless integration with React's server components.

---

### **2.2 Creating Static Routes by Creating Files**

Static routes are created simply by adding files to the `app` directory. Each file corresponds to a specific route in your application.

#### **Example of Creating a Static Route:**

1. Create a new folder named `about` in the `app` directory:
   
   ```
   app/about/page.js
   ```

2. Inside `page.js`, add the following code:

   ```javascript
   export default function AboutPage() {
     return <h1>About Us</h1>;
   }
   ```

3. Now, the About page can be accessed at `http://localhost:3000/about`.

---

### **2.3 Creating Dynamic Routes Using `[param]`**

Dynamic routes can be created using square brackets `[]` to define route parameters. This allows for more flexible routing based on user input or other variables.

#### **Example of Creating a Dynamic Route:**

1. Create a new folder named `posts` and a file named `[id].js` inside it:

   ```
   app/posts/[id]/page.js
   ```

2. Inside `page.js`, add the following code to handle the dynamic route:

   ```javascript
   export default function PostPage({ params }) {
     const { id } = params;
     return <h1>Post ID: {id}</h1>;
   }
   ```

3. Accessing a post by its ID can now be done at `http://localhost:3000/posts/1`, where `1` can be any post ID.

---

### **2.4 Nested Routes Using Folder Structure**

Nested routes allow you to create a hierarchy of routes, enhancing the organization of your application. You can achieve this by creating folders within the `app` directory.

#### **Example of Creating Nested Routes:**

1. Create a new folder structure for a blog:

   ```
   app/blog/page.js
   app/blog/[id]/page.js
   app/blog/[id]/comments/page.js
   ```

2. Define the main blog page in `blog/page.js`:

   ```javascript
   export default function BlogPage() {
     return <h1>Blog Home</h1>;
   }
   ```

3. Define the dynamic post page in `blog/[id]/page.js`:

   ```javascript
   export default function PostPage({ params }) {
     const { id } = params;
     return <h1>Blog Post ID: {id}</h1>;
   }
   ```

4. Define comments for a post in `blog/[id]/comments/page.js`:

   ```javascript
   export default function CommentsPage({ params }) {
     const { id } = params;
     return <h1>Comments for Post ID: {id}</h1>;
   }
   ```

5. Access the blog and comments at `http://localhost:3000/blog` and `http://localhost:3000/blog/1/comments`.

---

### **2.5 Default `layout.js` Files and How Layouts Work in App Router**

Layouts in the App Router allow you to define shared UI components for a group of routes. A `layout.js` file can be placed in a directory to create a consistent layout for all pages within that directory.

#### **Example of Using `layout.js`:**

1. Create a `layout.js` file in the `blog` directory:

   ```
   app/blog/layout.js
   ```

2. Define the layout structure:

   ```javascript
   export default function BlogLayout({ children }) {
     return (
       <div>
         <header>
           <h1>My Blog</h1>
         </header>
         <main>{children}</main>
         <footer>Footer content here</footer>
       </div>
     );
   }
   ```

3. Now, all pages under the `/blog` route will share this layout.

---

### **2.6 Loading and Error UI Using `loading.js` and `error.js`**

Next.js allows you to define loading and error states for your routes using `loading.js` and `error.js` files. This feature enhances the user experience by providing feedback while data is being fetched or when an error occurs.

#### **Example of Using `loading.js`:**

1. Create a `loading.js` file in the `app/posts` directory:

   ```
   app/posts/loading.js
   ```

2. Define the loading UI:

   ```javascript
   export default function Loading() {
     return <h2>Loading posts...</h2>;
   }
   ```

#### **Example of Using `error.js`:**

1. Create an `error.js` file in the `app/posts` directory:

   ```
   app/posts/error.js
   ```

2. Define the error UI:

   ```javascript
   export default function Error({ error }) {
     return <h2>Error loading posts: {error.message}</h2>;
   }
   ```

3. If an error occurs while fetching posts, the user will see the error UI instead of a blank page.
