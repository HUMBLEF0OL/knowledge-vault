## **Chapter 1: Introduction and Setup**

### **1.1 What is Next.js?**
Next.js is a **React framework** that enables you to build **server-rendered** and **statically generated websites** with ease. It enhances the standard React setup with features like **file-based routing**, **server-side rendering (SSR)**, **static site generation (SSG)**, and more.

- **Key Benefits**:
  - **Server-Side Rendering (SSR)**: Allows pages to be rendered on the server before they are sent to the client.
  - **Static Site Generation (SSG)**: Pre-generates pages at build time, making them highly performant.
  - **API Routes**: You can build backend APIs within the same project.
  - **File-based Routing**: Pages are automatically routed based on the file structure in the `pages/` or `app/` directories.
  - **Full-Stack Support**: Build both frontend and backend with a single framework.
  - **SEO-friendly**: Pre-rendering and metadata management make Next.js apps more discoverable by search engines.

---

### **1.2 Difference Between App Router and Pages Router**

Next.js 13 introduced the **App Router**, which replaces the older **Pages Router** approach. The App Router is part of the **app/ directory**, whereas the Pages Router was based on the **pages/ directory**.

#### **Key Changes**:
- **File-based routing** in both approaches, but the App Router allows for **colocation of components, layouts, and pages** in a more structured manner.
- **Server and Client Components**: The App Router introduces Server Components by default. Components can be server-rendered, reducing client-side JS and improving performance.
- **Layouts and Pages**: The App Router allows for nested layouts that persist across pages.
  
#### **Practical Example**:
In the **App Router** (`app/ directory`):
```bash
app/
├── layout.js        # Shared layout
├── page.js          # Index page
├── about/
│   ├── page.js      # About page
│   └── layout.js    # Nested layout for the about page
```

In the older **Pages Router** (`pages/ directory`):
```bash
pages/
├── index.js        # Index page
├── about.js        # About page
```

**App Router benefits**:
- Colocation of files for better modularity
- Server-side components that can fetch data directly
- Improved flexibility for layouts and loading/error handling

### **1.3 Installation and Initial Setup**

Let’s get hands-on by setting up a Next.js project.

#### **1.3.1 Installation**
You can create a new Next.js project with the latest version using the following command:

```bash
npx create-next-app@latest
```

#### **Project Setup:**
- Select **TypeScript** if you plan to use it for strict typing and better code reliability.
- **ESLint** can be added to enforce consistent code quality.
- **Tailwind CSS** can be preconfigured if you choose it as your styling option.

```bash
npx create-next-app@latest your-project-name
```

#### **1.3.2 Understanding Project Structure**

When you create a new Next.js project with the App Router, the structure looks like this:

```bash
your-project-name/
├── app/                # App Router
│   ├── layout.js       # Layout for all pages
│   ├── page.js         # Root page (e.g., "/")
│   ├── about/
│   │   └── page.js     # About page
├── public/             # Static assets like images
├── styles/             # Global CSS styles
├── next.config.js      # Configuration file for Next.js
├── package.json        # Project metadata and dependencies
```

- `app/`: Houses the **App Router**. Each folder inside `app/` represents a route, and `page.js` files represent the pages.
- `layout.js`: Defines a layout that is shared across all routes within the folder.
- `public/`: Static files like images can be stored here.
- `styles/`: Global CSS or other style files.
- `next.config.js`: Configuration options for your Next.js project.

### **1.4 Running the Application**
Once installed, you can run your application with:

```bash
npm run dev
```

This starts a local development server at `http://localhost:3000`, and you can now start building pages and exploring the new App Router.

#### **App Router Example**:
Here’s a basic example of a **Home Page** using the new App Router:

**`app/page.js`:**
```jsx
export default function Home() {
  return (
    <div>
      <h1>Welcome to Next.js with App Router</h1>
    </div>
  );
}
```

You can create additional routes by adding new folders or files in the `app/` directory.

---

### **1.5 Project Scripts**
In your `package.json`, you’ll find the following important scripts:

```json
"scripts": {
  "dev": "next dev",            // Runs the development server
  "build": "next build",        // Builds the app for production
  "start": "next start",        // Runs the built app in production mode
  "lint": "next lint"           // Lints the project for code quality
}
```

- **`npm run dev`**: Starts the development server with hot reloading.
- **`npm run build`**: Creates an optimized production build.
- **`npm run start`**: Runs the production build of the app.
- **`npm run lint`**: Checks for code issues based on ESLint configuration.

### **1.6 Next.js Dev Tools**
When working on a Next.js project, you'll often use the **Next.js Dev Tools**:

- **Hot Reloading**: Changes in your files automatically reload in the browser without needing to refresh.
- **Error Overlay**: Next.js shows an error overlay in the browser if there’s a runtime or build error.
- **ESLint**: Integrated ESLint helps with catching errors and enforcing coding standards.
