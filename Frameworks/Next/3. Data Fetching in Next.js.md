## **Chapter 3: Data Fetching in Next.js**

Data fetching is a crucial aspect of building applications in Next.js. This chapter will delve into various methods for fetching data, comparing old and new approaches, and understanding when to use each method.

---

### **3.1 `getServerSideProps` vs `getStaticProps` vs Client-Side Fetching (Old API vs New Approach)**

Next.js provides several methods for fetching data, each with distinct use cases. The primary methods are `getServerSideProps`, `getStaticProps`, and client-side fetching.

#### **1. `getServerSideProps` (SSR)**

- **Definition**: A function that runs on the server for every request. It fetches data before rendering the page.
- **Use Case**: Ideal for dynamic data that changes frequently and needs to be fetched with each request.

```javascript
export async function getServerSideProps(context) {
  const res = await fetch(`https://api.example.com/data`);
  const data = await res.json();

  return {
    props: { data }, // Will be passed to the page component as props
  };
}
```

#### **2. `getStaticProps` (SSG)**

- **Definition**: A function that runs at build time to fetch data and generate static pages.
- **Use Case**: Suitable for data that does not change often, such as blog posts, where performance and SEO are essential.

```javascript
export async function getStaticProps() {
  const res = await fetch(`https://api.example.com/data`);
  const data = await res.json();

  return {
    props: { data },
    revalidate: 10, // Re-generate the page at most once every 10 seconds
  };
}
```

#### **3. Client-Side Fetching**

- **Definition**: Fetching data using standard JavaScript methods (like `fetch()`) directly in React components after the initial render.
- **Use Case**: Useful for data that changes frequently and doesn’t need to be available at the initial load.

```javascript
import { useEffect, useState } from 'react';

function MyComponent() {
  const [data, setData] = useState(null);

  useEffect(() => {
    const fetchData = async () => {
      const response = await fetch(`https://api.example.com/data`);
      const result = await response.json();
      setData(result);
    };
    fetchData();
  }, []);

  return <div>{data ? data : 'Loading...'}</div>;
}
```

---

### **3.2 Using `fetch()` Directly in Components for Server-Side Data Fetching**

Next.js allows the use of the `fetch()` API within components. However, to take full advantage of server-side capabilities, use `getServerSideProps` or `getStaticProps`.

#### **Example of Using `fetch()` in a Component:**

```javascript
import React from 'react';

const Page = () => {
  const [data, setData] = React.useState(null);

  React.useEffect(() => {
    const fetchData = async () => {
      const response = await fetch('https://api.example.com/data');
      const result = await response.json();
      setData(result);
    };
    
    fetchData();
  }, []);

  return <div>{data ? JSON.stringify(data) : 'Loading...'}</div>;
};

export default Page;
```

In this example, data fetching occurs on the client-side, meaning the user will see a loading state until the data is fetched.

### **3.3 Static Generation with `getStaticProps` (Static Site Generation)**

Static Site Generation (SSG) allows you to pre-render pages at build time. This enhances performance and is beneficial for SEO.

#### **Example of Static Generation:**

1. **Creating a Page with `getStaticProps`:**

```javascript
// pages/blog/[id].js

export async function getStaticProps({ params }) {
  const res = await fetch(`https://api.example.com/posts/${params.id}`);
  const post = await res.json();

  return {
    props: { post }, // Will be passed to the page component as props
  };
}
```

2. **Generating Paths with `getStaticPaths`:**

For dynamic routes, you can generate paths based on your data:

```javascript
export async function getStaticPaths() {
  const res = await fetch(`https://api.example.com/posts`);
  const posts = await res.json();

  const paths = posts.map((post) => ({
    params: { id: post.id.toString() },
  }));

  return { paths, fallback: false }; // false means 404 for non-existent pages
}
```

### **3.4 Server-Side Rendering (SSR) Using Server-Side Data Fetching**

Server-Side Rendering (SSR) allows you to fetch data on each request and serve the fully rendered page to the client. This is done using `getServerSideProps`.

#### **Example of SSR:**

```javascript
// pages/user/[id].js

export async function getServerSideProps({ params }) {
  const res = await fetch(`https://api.example.com/users/${params.id}`);
  const user = await res.json();

  return {
    props: { user },
  };
}
```

In this scenario, every time the user accesses the page, Next.js will fetch the user data from the API and render it on the server before sending the HTML to the client.

---

### **3.5 Client-Side Data Fetching with `useEffect`**

Client-side fetching is appropriate for user interactions and data that can change dynamically without needing to refresh the entire page.

#### **Example of Client-Side Data Fetching:**

```javascript
import React, { useEffect, useState } from 'react';

function UserProfile({ userId }) {
  const [user, setUser] = useState(null);

  useEffect(() => {
    const fetchUser = async () => {
      const response = await fetch(`https://api.example.com/users/${userId}`);
      const data = await response.json();
      setUser(data);
    };

    fetchUser();
  }, [userId]);

  return <div>{user ? user.name : 'Loading...'}</div>;
}
```

In this example, the user data is fetched based on the user ID, which could be passed as a prop from a parent component.

### **3.6 Incremental Static Regeneration (ISR) and Revalidation**

Incremental Static Regeneration allows you to update static pages after the build time. This means you can re-generate pages in the background based on defined intervals.

#### **How ISR Works:**

- Use the `revalidate` option in `getStaticProps` to specify a time interval for page regeneration.

```javascript
export async function getStaticProps() {
  const res = await fetch('https://api.example.com/data');
  const data = await res.json();

  return {
    props: { data },
    revalidate: 60, // Re-generate the page at most once every 60 seconds
  };
}
```

With ISR, when a user accesses the page, if the revalidation period has passed, Next.js will regenerate the page in the background and serve the new version on the next request.
