## **Chapter 8: Static Site Generation (SSG) and Incremental Static Regeneration (ISR)**

Next.js provides powerful features for generating static pages, improving performance and SEO. This chapter delves into **Static Site Generation (SSG)** and **Incremental Static Regeneration (ISR)**, explaining how to pre-render pages at build time and how to leverage ISR for dynamic content updates.

---

### **8.1 Pre-rendering Pages at Build Time with SSG**

**Static Site Generation (SSG)** is a method of pre-rendering pages at build time. This means that the HTML for each page is generated once during the build process and can be served quickly to users. SSG is ideal for content that doesn't change frequently and can benefit from fast loading times.

#### **How to Implement SSG**

To implement SSG in Next.js, you use the `getStaticProps` function. This function fetches data at build time and provides it as props to the page component.

**Example of Using `getStaticProps`:**

```javascript
// pages/posts.js
import Link from 'next/link';

export default function Posts({ posts }) {
  return (
    <div>
      <h1>Blog Posts</h1>
      <ul>
        {posts.map(post => (
          <li key={post.id}>
            <Link href={`/posts/${post.id}`}>{post.title}</Link>
          </li>
        ))}
      </ul>
    </div>
  );
}

// Fetching data at build time
export async function getStaticProps() {
  const res = await fetch('https://api.example.com/posts');
  const posts = await res.json();

  return {
    props: {
      posts,
    },
  };
}
```

- **Fetching Data**: The `getStaticProps` function fetches data from an API or database.
- **Returning Props**: The data is returned as props to the component, which is then used to render the static page.

#### **Benefits of SSG**

- **Performance**: SSG pages are served as static HTML, resulting in faster load times.
- **SEO**: Search engines can easily index static pages, improving visibility.
- **Scalability**: Pre-rendered pages can handle high traffic without additional server load.

### **8.2 Using ISR for Incremental Builds and Page Revalidation**

**Incremental Static Regeneration (ISR)** allows you to update static content after the build process without needing to rebuild the entire site. With ISR, you can specify which pages should be regenerated based on certain conditions.

#### **How to Implement ISR**

To implement ISR, you can use `getStaticProps` along with the `revalidate` key in the returned object. This key specifies how often the page should be revalidated.

**Example of Using ISR:**

```javascript
// pages/posts/[id].js
export default function Post({ post }) {
  return (
    <div>
      <h1>{post.title}</h1>
      <p>{post.content}</p>
    </div>
  );
}

// Fetching data with ISR
export async function getStaticProps({ params }) {
  const res = await fetch(`https://api.example.com/posts/${params.id}`);
  const post = await res.json();

  return {
    props: {
      post,
    },
    revalidate: 10, // Revalidate every 10 seconds
  };
}

// Specify dynamic routes for SSG
export async function getStaticPaths() {
  const res = await fetch('https://api.example.com/posts');
  const posts = await res.json();

  const paths = posts.map(post => ({
    params: { id: post.id.toString() },
  }));

  return {
    paths,
    fallback: 'blocking', // Use blocking mode for ISR
  };
}
```

- **Dynamic Routes**: In the example, we fetch data for a specific post using dynamic routes.
- **Revalidation**: The `revalidate` key indicates that the page should be revalidated every 10 seconds, allowing for updated content without a full rebuild.

#### **Benefits of ISR**

- **Dynamic Updates**: Content can be updated automatically at specified intervals, ensuring users see the latest information.
- **Efficiency**: Only specific pages are regenerated, reducing the need for full site builds.

---

### **8.3 Setting Revalidation Intervals for Static Content**

You can customize the revalidation interval based on the specific needs of your application. This flexibility allows you to balance between performance and data freshness.

#### **Example of Setting Different Revalidation Intervals:**

```javascript
export async function getStaticProps() {
  const res = await fetch('https://api.example.com/stats');
  const stats = await res.json();

  return {
    props: {
      stats,
    },
    revalidate: 60, // Revalidate every 60 seconds for stats
  };
}
```

- **Shorter Intervals**: For data that changes frequently (like stats), set a shorter revalidation interval.
- **Longer Intervals**: For static content that doesn’t change often (like blog posts), you might set a longer interval.
